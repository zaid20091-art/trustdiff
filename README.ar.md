# TrustDiff — الكود المصحوب بأدلة قابلة للتحقق

**المشكلة التي يعالجها:** قد ينجح وكيل البرمجة في اختباراته ثم يرسل تغييرًا يوسّع الصلاحيات أو يكسر نظامًا آخر. TrustDiff لا يمنح «الثقة» اعتمادًا على كلام الوكيل؛ بل يقيّم عقودًا يملكها المراجع، ويسجّل الأدلة والمخاطر غير المفحوصة.

**الإصدار التجريبي 0.4.0.** يوضح [تقرير التدقيق](docs/reports/0.4.0-AUDIT.md) نتائج الاختبارات وحدود التحقق.

## ما أُنجز بالفعل

1. تحميل العقود من Commit الأساس الموثوق حتى لا يُضعفها Pull Request نفسه، ورفض تغيير السياسة دون مراجعة مستقلة.
2. تشغيل الاختبارات في Docker بشبكة معطّلة ومصدر للقراءة فقط وصلاحيات وموارد مقيّدة. إذا لم تتوفر البيئة المعزولة يفشل التحقق بدلًا من الادعاء بالنجاح. Docker ليس عزلًا بمستوى آلة افتراضية.
3. ربط المخاطر بالعقود المطلوبة: تغييرات الصلاحيات والأموال والأسرار وCI وغيرها. الخطر الحرج دون عقد إلزامي ناجح يمنع القبول.
4. رسم اعتماد ساكن لملفات Python وJavaScript وTypeScript، وكشف إشارات إضعاف الاختبارات، وإظهار المجهول صراحة.
5. إنشاء اختبار مضاد **قابل للتنفيذ** لحالة ضيقة: دالة Python تحمل اسم `can_access_admin(role)` أو اسمًا مدعومًا مماثلًا. الاختبارات الأخرى مقترحات وليست نتائج تشغيل.
6. تقارير JSON وHTML وMarkdown وSARIF، وسجل SHA-256 مرتبط، وحزمة إثبات قابلة للنقل يمكن توقيعها بمفتاح Ed25519 مستقل.
7. سير عمل GitHub لطلبات السحب، وإضافة VS Code للتشخيص المحلي، وجسر MCP للقراءة فقط.

## التشغيل والنشر

بعد فك ZIP داخل مجلد المشروع:

```bash
git init -b main
git add .
git commit -m "Initial TrustDiff"
python3 -m pip install -e .
python3 -m unittest discover -s tests -v
python3 fixtures/security-regression/run_demo.py
```

للتشغيل الآمن نسبيًا يجب توافر Docker:

```bash
docker pull python:3.11-slim
IMAGE="$(docker image inspect python:3.11-slim --format '{{index .RepoDigests 0}}')"
trustdiff check --baseline HEAD --runner docker --image "$IMAGE" --challenge-mode run
trustdiff report --format html --output .trustdiff/report.html
```

استخدم بصمة التزام الأساس المعتمد عند فحص طلب سحب. لضبط شرط الدمج على التزام الطلب نفسه، اربط الفحص **TrustDiff Independent Verification** بتطبيق GitHub المثبّت من إعدادات قواعد الفرع. [خطوات الإعداد](docs/INTEGRATIONS.md)

**تنبيه أساسي:** التوقيع الذاتي من جهاز وكيل البرمجة لا يعني دليلًا مستقلًا. يجب إدارة مفتاح التوقيع ومخزن المفاتيح المعتمدة خارج صلاحيات الوكيل. راجع [التكاملات](docs/INTEGRATIONS.md) و[التهديدات والحدود](docs/THREAT_MODEL.md) و[خارطة الطريق](docs/ROADMAP.md).
