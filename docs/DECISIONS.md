# Architectural decisions — 0.3.1

1. **Keep a deterministic Python core:** no mandatory LLM/AI provider. The target is an auditable review gate, not a coding agent. A future Rust core is possible only if independent performance/security measurements justify its complexity.
2. **Split authority from execution:** candidate PR code is untrusted; baseline-owned contracts and a pinned verifier determine obligations. Production signers must be on separately managed infrastructure.
3. **Fail closed rather than guess:** a missing trusted baseline policy, unknown contract checker, dirty candidate tree, failed contract or uncovered critical risk is a nonzero outcome.
4. **Use a bounded runner:** restricted Docker is an accessible alpha implementation; a VM is the hardened target. `--allow-host-execution` is a test-only opt-in.
5. **Sign statements, not confidence:** the Ed25519 envelope binds declared evidence to Git commit and policy hash, and explicitly excludes an absence-of-bugs claim. Trust store must be independent.
6. **Avoid overbroad generated tests:** start with a documented `can_access_admin(role)` negative-role oracle that can run automatically; expose other challenge ideas as unexecuted suggestions.
7. **Respect existing workflows.** GitHub checks, portable artifacts, and optional contributor guidance support existing development tools.
8. **Reading is not trusting (0.3.1):** every consumer of `.trustdiff/latest.json` goes through `EvidenceValidator`. A verdict is presented as trusted only with a valid signature from an externally provisioned signer, bound to the current commit; a local hash chain is reported as tamper-evidence, never as authentication. Trust anchors located inside the repository are ignored. Untrusted report text is sanitised and labelled as data because MCP output is consumed by language-model agents.
9. **The verifier is pinned outside the branch (0.3.1):** the gate loads from the base branch (`pull_request_target`), runs the base commit's verifier, and refuses it unless its digest equals an organisation-held value computed by independent inline code. Signing lives in a separate, environment-protected job. Rejected: trusting the verifier's own digest output (a neutered verifier answers anything); running candidate code on the host to "prepare" the test (pwn-request pattern).
10. **Everything from the repository is hostile input (0.3.1):** git runs with execution-capable options neutralised and repos with such config are refused; paths are NUL-delimited and diffs per literal path; files/diffs/output/regexes are bounded; overflow and timeouts are ERROR, never PASS.
11. **Isolation is layered and honest (0.3.1):** Docker with minimal exposure by default (clean commit snapshot, no network, dropped capabilities, bounded resources, kill-by-name cleanup). Stronger isolation = an allow-listed OCI runtime (gVisor/Kata) behind identical flags, failing closed. We do not claim container isolation equals a VM.
12. **Evidence carries its own context (0.3.1):** v2 bundles sign signer identity, time, verifier digest, commit, policy and runner. Keys rotate by window and revoke absolutely; policy changes can carry signed approvals; a write-once log can sit on storage the agent cannot touch. Legacy v1 stays verifiable but flagged.
