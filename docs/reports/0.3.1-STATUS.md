## ما وُجد وأُصلح (ملخص)
1. MCP يعرض أي JSON محلي كـ `READY/PASS` (P0-01). 2. الـ gate القديم يمكن تعديله من PR، والمحقق بلا بصمة معتمدة (P0-02). 3. **`.git/config` يجعل المحقق ينفّذ أوامر المهاجم** (P0-02/05) — مثبت. 4. مخرجات غير محدودة 400MB (P0-03/05) — مثبت. 5. ReDoS في ماسح JS (ملف 60KB يعلّق >10s) — مثبت. 6. `RecursionError` يُسقط البوابة — مثبت. 7. أسماء الملفات (Unicode / مسافة+`b/`) تُخفي المسار فتتخطى الاختبارات المضادة أو تنسب الخطر لملف آخر — مثبت. 8. حاوية تبقى بعد المهلة، وجذر المستودع بـ`.git`/الأسرار مقروء داخل الحاوية (من الشيفرة) . 9. تقارير/عقود/حزم/مخازن ثقة بأنواع غير متوقعة تنهار. 10. خلل في كودي أنا كشفه الـ fuzzing (TypeError على verdict غير قابل للتجزئة). فرضية FIFO **نُفيت**.

## ما لم يُفعل أو لم يُختبر — اقرأه قبل الاعتماد
1. **لم يُشغَّل شيء على GitHub Actions** (لا شبكة). الـ workflows مفحوصة ساكنةً ومحاكاة PR مفصّلة محلياً فقط. جرّبوها على fork خاص أولاً.
2. **Docker الحقيقي لم يُشغَّل**؛ اختباراته (`RealDockerTests`) مكتوبة وتُشغَّل في job `docker-integration`.
3. **MicroVM:** لا backend Firecracker مباشر؛ العزل الأقوى = gVisor/Kata كبيئات تشغيل Docker ولم تُجرَّب.
4. SHA الخاصة بـ Actions: أربعة منها مرئية في مصادر متعددة، و`attest-build-provenance` من مصدر واحد — تحققوا بـ `gh api` (`docs/CI_PINS.md`). لم أستطع حلّها مقابل واجهة GitHub.
5. `requirements-signing.lock` لا يُشحن (يحتاج تجزئات من فهرسكم)؛ التوقيع في CI معطّل افتراضياً ويفشل مغلقاً بدونه.
6. التثبيت النظيف بـ `pip install .` لم يُختبر (لا setuptools/شبكة هنا)، ولا Python 3.10/3.11 (اختُبر 3.12 فقط؛ الـ CI يغطيها).
7. خادم MCP الحقيقي (stdio) لم يُجرَّب؛ استُخدم بديل يلتقط الدوال الحقيقية.
8. النتائج **الفاشلة** لا يمكن توقيعها؛ تظهر كادعاء. الموافقات الموقّعة قابلة للتحقق لكن البوابة لا تشترطها بعد. المخزن «مرة واحدة» على قرص عادي = كشف عبث فقط. لا موصّل S3 Object Lock.
9. تغيير سلوكي مقصود: الاختبارات تعمل على commit الهدف لا شجرة العمل؛ MCP يُرجع كائنات لا قوائم؛ يجب ضبط متغيرات البوابة (`docs/MIGRATION_0.3.0_to_0.3.1.md`).
