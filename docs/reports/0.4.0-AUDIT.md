# TrustDiff 0.4.0 alpha release audit

Reviewed input archive `TrustDiff-0_3_1-Security-Hardening.zip` with SHA-256
`c31a81cf6911bb32d893c1757b8c38513e3186e12ce543bd531c6a9098ab2647`.
The original archive had 167 Python tests. A fresh run in the development
environment produced 78 passes, 51 failures, 30 errors and 8 skips. Windows
Git LFS configuration, filesystem permissions and executable assumptions
accounted for many of those failures. The earlier report in the archive
describes a separate environment.

## Acceptance and remaining scope

| Area | Implementation and local acceptance | Remaining gap |
|---|---|---|
| Git configuration and snapshots | Standard LFS filters neutralized, custom executable configuration refused, raw committed blobs exported. Real Git and Git LFS exercised for clean hydration and corrupt or missing objects. | LFS fetch and external object-cache provisioning are operator-managed. Snapshot limits and portable path restrictions apply. |
| Windows and POSIX | Windows Job Objects supervise processes. Portable file names, symlink-aware tests, and a Windows/Linux CI matrix cover Python 3.10–3.13. | Windows 3.13 was the local runtime. The Linux CI matrix, other Python versions and Windows symlink ACL scenarios require runner execution. |
| Counterexamples | Baseline-anchored Python call sequences and reviewer-specified expectations. Fixtures cover authorization, money, data preservation and API compatibility. | No general oracle generator or multi-language adapter. Candidate code shares its process with the observation worker. A hostile implementation can manipulate its output. |
| Independent verification | External state, full approved commit, verifier digest, optional pinned container runtime, separate signing job. Real Git scenarios check policy edits, modified verifier code and module shadowing. | Real Docker daemon, Kata/gVisor and GitHub runner were unavailable. No independent hosted verifier, remote key custody or isolation certification was deployed. |
| Reproduction and repair | Approved case replay preserves original inputs and expectations. A passing descendant repair triggers the full gate. Local fixture uses real commits and subprocesses with the execution environment substituted. | Automatic patch generation, live isolated replay and automatic repair delivery are open. |
| GitHub | Protected workflow and exact-head App publisher bind repository, base, head, policy and verifier. Static workflow tests and a simulated Checks API verify the path. | App registration, webhook handling, fork/merge-queue runs, required-check rulesets, signer dependency lock and hosted signing require deployment. |
| VS Code and tool-neutral diagnostics | Workspace Trust, user-owned executable, manual review and opt-in debounced review on save. Editor helper tests cover path enforcement and diagnostic rendering. | A live extension-host and Marketplace run were outside local acceptance. Agent integrations can consume CLI JSON or MCP, whose live transport was unavailable. |
| Evidence protocol | MIT-licensed wire schema and Ed25519 v2 verification. Supports approved signed PASS and FAIL, including a merge consumer that continues to require PASS by default. Tests cover tampering, replay and cross-repository publication. | External WORM storage, enterprise key management, independent timestamping and cross-language conformance remain open. |
| Benchmark | Four synthetic mutants were caught by boundary probes beyond the smoke checks. Four controls passed. Raw results are reproducible with the included benchmark. | Thousands of real changes, competing-tool comparisons, production latency, cost and false-positive measurements remain open. |

Git configuration and source checks assume the verifier controls its operating
system, executable search path, dependencies, Docker endpoint, repository
checkout, and key directory. Untrusted candidate code is evaluated through
isolated execution. Keep the verifier and signer outside the candidate's
administrative reach. See [the threat model](../THREAT_MODEL.md).

The optional extended engineering constitution was absent from the workspace
and source archive. The supplied project rules and repository threat model
guided the review.

## Repeat local acceptance

```text
python -m unittest discover -s tests -v
python fixtures/security-regression/run_demo.py
python fixtures/security-regression/benchmark.py
node --test integrations/vscode/extension.test.js
```

On 14 November 2026, the full Python suite ran in six batches from a clean
extraction on Windows 11 with Python 3.13.9 and Git 2.53.0.windows.2.
Of 174 tests collected, 160 passed, 14 were skipped and none failed. Seven
skips require Docker, one requires Docker and a registered isolation runtime,
five require symlink permission and one needs a POSIX filename. The two
editor tests and the authorization demo also passed. The Python wheel built
offline from the extracted source and installed into a fresh virtual
environment. Its CLI reported the same verifier digest as the source
checkout and correctly diagnosed an untracked authorization file. The
[machine-readable record](0.4.0-RESULTS.json) carries the suite results and
raw synthetic benchmark measures.

and [the protocol](../EVIDENCE_PROTOCOL.md) for evidence verification.
